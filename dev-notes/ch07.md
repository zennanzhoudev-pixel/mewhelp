# Ch07 会话上下文管理 · 开发留痕

## 目标
三层历史结构:最近留原文、中间按规则截短、最远异步压成梗概;token 预算从模型窗口倒推;上下文拼装固定顺序保前缀缓存;前端多会话侧栏。

## 关键决策
- 两个锚点 id(summary_upto_msg_id / layer1_from_msg_id)划边界,降级只挪 id 不搬数据;梗概单开会话摘要表。
- 摘要后台异步触发,压完不回头重写,旧梗概只作背景;触发看用量不数条数(工具结果不落消息表)。
- 调模型上下文固定顺序:system(人设/红线/工具定义)打头 → 中间截短层 → 最近原文 → 用户当前话 → 早期梗概+检索证据合成一条挂用户句后。梗概不许单占 system(会打碎前缀缓存)。
- token 预算 = 模型窗口扣掉固定开销与单轮 ReAct 峰值后再分给历史;中文按字数折 token 的口径随预算一起校准。

## 交付物
- `app/core/{memory,summarizer}.py` 升级、`sql/ch07-ddl.sql`、`app/api/conversations.py`、前端会话侧栏
- `tests/test_{context_assembly,summarizer,conversations_api,prompt_cache_prefix}.py`、`scripts/eval_ch07.py`

`make eval-ch07`;grep `model_ctx` / `history_ctx` 看每轮实际发出的上下文;聊二十轮以上 token 不爆、后台摘要不阻塞回复。

## 需用户独立完成
- 真实长对话验证摘要与滑窗;默认窗口下聊二十轮不应触发降级/摘要(装得下就不压)。
