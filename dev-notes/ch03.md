# Ch03 RAG 基础 · 开发留痕

## 目标
把 `query_faq` 内部从关键词查表升级为 BGE-M3 向量语义检索,建起 MySQL 权威源 + Milvus 双写的知识库,入参出参契约不变。

## 关键决策
- 嵌入走 SiliconFlow 的 `BAAI/bge-m3`(OpenAI 兼容),向量库 Milvus(Standalone,唯其支持 BM25)。
- 双写:先写 MySQL 记 pending,再向量化回填 `vector_id`、转 done;按主键 upsert,挂了重跑只捡 pending。
- 切块:结构感知标题切 + 递归切 + 句末重叠 + 大表格按行切复制表头。
- 录入页 `/kb`:切块/录入/补向量/检索自测/作业白名单,页面与 CLI 同读一份 `sources.py` 与 `build_chunks`。

## 交付物
- `app/kb/{chunking,documents,dedup,mining,dualwrite,milvus_client,sources}.py`
- `app/core/{embeddings,retrieval}.py`、`app/api/{kb,jobs,admin}.py`、`app/core/jobs.py`
- `sql/ch03-ddl.sql`、`sql/ch03-seed.sql`、`data/kb/*.md`、`scripts/{build_kb,vectorize_kb,mine_knowledge,eval_retrieval,eval_mining,smoke_embed}.py`

## 测试结论
- 切块/去重/文档映射纯逻辑 TDD 全绿(无需外部服务)。
- 双写幂等恢复、Milvus 检索、KB 录入 API 需 MySQL + Milvus + 嵌入上游,由用户起服务后跑。

## 需用户独立完成
- 填 `EMBED_API_KEY` 后跑 `scripts/smoke_embed.py`(维度 1024 GO);起 MySQL/Milvus 后 `make kb-build && make kb-vectorize` 并浏览器验收 `/kb` 与聊天页语义召回。
