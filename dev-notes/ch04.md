# Ch04 RAG 进阶 · 开发留痕

## 目标
混合检索(Milvus 原生 BM25 + dense,hybrid_search RRF)+ bge-reranker-v2-m3 精排 + 生成质量控制(引用/拒答/自评落池)+ 四策略评估体系。

## 关键决策
- 基础设施:Milvus Lite → Standalone(唯 Standalone 支持原生 BM25 全文检索)。
- `query_faq` 升级为完整 RAG 管线:Query 理解 → 混合召回 → 重排 → 两道生成前证据闸(检索分闸 + 自评闸)→ 带编号证据回传。
- 生成前结构化自评用扁平字段 `useful/reason`(避开上游对嵌套对象数组的 502)。
- 评估:四策略(纯向量/纯 BM25/混合/混合加重排)分桶,检索段 Recall@5/MRR + 证据覆盖度(确定性)+ 生成段(答案覆盖度/忠实度/拒答率)。产物 `rag_eval.json` 给页面只读,不重算。

## 交付物
- `app/kb/milvus_client.py`(新 schema + hybrid/dense/bm25)、`app/core/{rerank,query_understanding,selfcheck,retrieval}.py`
- `sql/ch04-ddl.sql`(low_confidence_questions + faith_cases)、`app/api/rageval.py`
- `scripts/{smoke_rerank,smoke_milvus_bm25,eval_ch04,validate_eval_ch04,judge_check}.py`、`tests/data/eval_ch04.jsonl`

## 测试结论
- rerank/selfcheck/retrieval 策略分支/query_faq 管线纯逻辑 TDD 全绿(mock)。
- Milvus 混合检索、低置信池 DB 写入、真实建库与四策略报告需 Standalone + MySQL + 上游,由用户起服务后跑。

## 需用户独立完成
- 填 `RERANK_API_KEY` 后跑 `make smoke-rag`(BM25 + rerank 双红线);起服务后 `make eval-rag` 出四策略报告,浏览器验收引用可点、库外拒答入池。
