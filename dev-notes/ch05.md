# Ch05 Workflow + Agent 混合架构 · 开发留痕

## 目标
用 LangGraph 把客服后端重构成「确定性 Workflow 骨架 + 主力 Agent 核心节点」的混合架构,两个 API 入口都走图,前端加转人工/建工单按钮。

## 关键决策
- checkpointer = AsyncSqliteSaver(LangGraph 无官方 MySQL checkpointer;自带且持久,与 MySQL 业务库解耦)。
- 置信度闸在 forced_rag 之后、agent 之前(生成前证据闸),仅知识路;业务路不设闸。
- create_ticket 在 Agent 内拦截为「提议」:不写库,转成前端可选项;写库只在 `/api/actions/create-ticket` 按钮端点发生。
- `query_logistics` 入参改 `tracking_no`(只能从 `query_order` 返回里取到),让「先查订单再查物流」的 ReAct 多步真实成立。
- 两入口都走图:流式 `astream(stream_mode=["messages","updates"])`,非流式 `ainvoke`。

## 交付物
- `app/graph/{state,routing,nodes,build,runtime}.py`、`app/core/intent.py`、`app/api/{chat,agent,actions}.py`
- `scripts/{smoke_langgraph,bare_agent_loop,eval_intent,eval_ch05}.py`

## 测试结论
- 分流/停止条件/State/reply 节点/forced_rag/Agent 节点/log/runtime 事件映射/build 拓扑均 TDD 全绿(mock 图与模型)。
- 五验收端到端(强制检索、Agent 自调工具、投诉两按钮、闲聊话术、ReAct 多步)需真实上游 + MySQL,由用户起全服务后跑 `make eval-ch05`。

## 需用户独立完成
- 起全服务后跑 `make eval-ch05`,并浏览器验收「我要投诉」出两独立按钮、转人工/建工单交互。
