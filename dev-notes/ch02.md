# Ch02 Function Calling 工具链 · 开发留痕

## 目标
用 `@tool` 定义 5 个业务工具,给客服聊天装「查数据」的能力;能力长在前端在用的 `/api/chat` 上,单轮收敛。

## 关键决策
- 编排:抽共享 `_prepare_turn` + `stream_agent_turn`(流式)/ `run_agent_turn`(非流式)两出口;收敛步不 `bind_tools`,强制单轮。
- 数据:MySQL 四表(conversations/messages/faq/tickets),商品/订单/物流走工具内 mock(入参为随机种子,可复现)。
- `create_ticket.conversation_id` 用 `InjectedToolArg` 系统注入,不暴露给模型;写类工具不自动重试。
- 测试:DB 测试连 Docker MySQL 的 `mewhelp_test`(不用 SQLite,ENUM/ON UPDATE/JSON 行为不一致)。

## 交付物
- `app/db/{base,models,repository}.py`、`app/tools/{business,registry,infra}.py`、`app/core/agent.py`、`app/api/agent.py`
- `sql/ch02-ddl.sql`、`sql/ch02-seed.sql`、`docker-compose.yml`
- `scripts/{smoke_toolcall.py,eval_agent.py,demo_agent.sh}`

## 测试结论
- 工具 mock、基础设施(超时/重试/错误回灌/写类不重试)、prompt、编排两出口均 TDD,单测可脱离 MySQL 跑(mock repository)。
- DB 往返与 tool-calling 冒烟需 MySQL + 真实上游,由用户起服务后跑。

## 需用户独立完成
- 起 Docker MySQL 并 `make seed`;填 `.env` 后跑 `scripts/smoke_toolcall.py`(go/no-go)与 `make eval-agent`。
