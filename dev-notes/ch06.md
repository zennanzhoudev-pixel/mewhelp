# Ch06 意图识别与对话管理 · 开发留痕

## 目标
把 ch05 的占位分流器升级成正式版:八类意图 → 五出口、指代消解做实、退款退货/售后确定性子流程、缺订单号走 interrupt/resume 订单选择器、退款工单落 tickets。

## 关键决策
- 意图识别走 LLM prompt 路线(不训分类模型),七类 + 「其他」兜底,强制 JSON 输出 intent + confidence;统一用大模型识别,小模型降级路只留配置种子不实现运行时。
- 指代消解 + Query 改写合并做:结合历史把「它能退吗」补全成独立可懂的问法,已完整的原样透传。
- Query 扩写只对退款退货/售后这类高频低容错场景做,多条查询一起检索再去重合并,只检索侧现查现用、不入库拆存。
- 退款退货/售后走 refund_flow 确定性子流程:先取订单 → 扩写并强制检索政策 → 最后只把「这一单能不能退」交给主力 Agent 判断。
- 缺订单号用 LangGraph interrupt 停在取订单节点,前端弹订单卡片让用户点选,resume 原地续跑(不重跑意图/检索)。

## 交付物
- `app/core/{coref,intent,query_understanding}.py` 重写、`app/graph/{nodes,build,routing,runtime,state}.py` 扩到五出口 + refund_flow
- `app/api/actions.py` 加 create-refund、`sql/ch06-ticket-type.sql`、`scripts/{smoke_interrupt,eval_ch06,eval_coref,eval_expand}.py`
- 前端订单选择器卡片 + 退款表单

## 验收
`make smoke-interrupt`(interrupt/resume 冒烟)、`make eval-ch06`(四验收端到端);浏览器验证意图切换、指代补全、退款子流程订单选择器。

## 需用户独立完成
- 填 `.env` 聊天上游后跑真实多轮意图/指代/退款子流程验收;本机无 Docker 时数据库与知识库由本地起服务。
