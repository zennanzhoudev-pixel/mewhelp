# 设计思路与设计原理

> 为什么长成现在这样：问题定义、核心思路、设计原则、关键取舍与失败模式。

## 1. 问题定义

电商客服是**高风险、强约束、高并发、长尾问法**的场景：

- 答错订单/物流/价格会直接引发客诉；
- 退款政策不能由模型自由承诺；
- 用户问法口语化、指代多、同义词多；
- 大量问题是重复的，应该沉淀而不是每次重算；
- 运营需要看见「钱花在哪、答得准不准、缺什么知识」。

因此目标不是「能聊天」，而是「**答得准、答得稳、可追溯、能进化**」。

## 2. 核心思路

### 2.1 Workflow 骨架 + Agent 核心

```
确定性骨架（LangGraph）负责「不能错的路」：
  指代 → 意图 → 分流 → 强制检索/取单 → 置信度闸 → 日志
主力 Agent（ReAct）负责「需要临场判断的路」：
  订单/物流/售后等多步工具组合
```

一句话原则：**能靠代码守住的可靠性，绝不交给模型的临场判断；需要开放推理的地方，才放开给 Agent。**

### 2.2 检索不是可选动作，而是轨道

知识类问题不允许「模型自己决定要不要查」。系统在图上写死 `retrieve_knowledge → confidence_check`，证据不足直接兜底，不进入生成。

### 2.3 退款是确定性子流程

退款/售后不允许模型凭记忆判断。流程写死为：取订单（缺号则中断让用户选）→ 强制检索政策 → 只把「这一单能不能退」交给模型。

### 2.4 答不好的问题必须回流

低置信、自评不足、用户点踩三入口入池，经标准化/查重/人工审核写回知识库，形成数据飞轮。

## 3. 设计原则

| 原则 | 落点 |
| --- | --- |
| 硬约束代码化 | 路由映射、强制检索、退款子流程、写工具权限、步数封顶 |
| 配置与代码分离 | 三组上游、阈值、预算全部 `.env` / `Settings` |
| 失败可解释 | 错误分层（404/422/502/503）、工具错误回灌、拒答而非硬编 |
| 结果可追溯 | 引用编号 + 章节路径、工具审计、Langfuse trace |
| 幂等可重跑 | 知识双写按主键 upsert、vectorize 只捡 pending、作业白名单 |
| 成本有意识 | token 预算、按意图成本账、前缀缓存、重排 Top-K 收敛 |
| 不阻塞主路径 | 后台摘要、旁路分类器、观测回调失败不影响业务 |
| 先度量再调优 | 300 题评估集、置信度阈值校准、裁判回归 |

## 4. 关键决策与权衡

| 决策 | 选择 | 备选与理由 |
| --- | --- | --- |
| 编排形态 | LangGraph 图 | 线性 Chain 撑不住分叉/汇合/ReAct 环/中断恢复 |
| 架构分工 | Workflow + Agent 混合 | 全 Agent 不可控、全 Workflow 不够灵活 |
| 检索 | dense + BM25 + RRF + rerank | 纯关键词漏同义、纯向量漏型号；BM25 补精确匹配，重排补语义 |
| 向量库 | Milvus Standalone（Lite → Standalone） | Lite 不支持原生 BM25 全文检索 |
| Query 扩写 | 只在检索侧、核心场景 | 入库侧拆存会膨胀且难维护 |
| 置信度闸位置 | 生成前 | 流式回答后再判已晚，弱证据必须短路 |
| 缺槽位 | interrupt/resume | 两轮重入会重跑意图/检索，语义漂移且浪费 |
| 工具参数 | JSON Schema + 注入参数 | 会话号/用户身份不许模型填，防伪造 |
| 写操作 | 权限门 + 确认流 + 不重试 | 重复建单比失败更糟 |
| 外部工具 | MCP + 我方权限 | Server 声明不可信，写清单只认我方 |
| 上下文 | 三层 + 摘要 + 锚点 | 全量塞会爆、只滑窗会忘；摘要异步不阻塞 |
| 去重 | 文本归一化（非向量） | 确定、便宜、可解释；向量只服务检索 |
| 微调 | RoBERTa 全参（非 LoRA） | 这个体量全参够用，LoRA 是大模型手段 |
| 分类器部署 | ONNX 旁路 | 实时主链路不承担推理延迟 |
| 上游接入 | 三组直连，无网关 | 单应用三上游，网关只增加进程与排障跳数 |

## 5. 失败模式与防线

| 失败模式 | 防线 |
| --- | --- |
| 模型编造订单/物流 | 工具查真实数据 + prompt 禁止臆造 + 证据引用 |
| 知识类不检索直接答 | 图上强制检索，不进 Agent 前先检索 |
| 检索召回但答不了 | 生成前自评 + 置信度阈值，拒答并落池 |
| 退款乱承诺 | 确定性流程 + 负面知识 + 政策引用 |
| 工具参数错 | JSON Schema 校验，错误回灌让模型追问 |
| 工具卡死 | 超时 + 只读重试 + 写操作不重试 |
| 重复建工单 | 确认流 + 写工具不自动重试 |
| 上下文爆/忘 | token 预算 + 三层历史 + 异步摘要 |
| 检索质量回退 | 评估集四策略对照 + 趋势 |
| 成本失控 | 按意图 token 账 + Top-K/预算可配 |
